# تجهيز OpenBTS-UMTS لـ USRP-2901

هذا الدليل يجهز البناء والفحص البرمجي حتى لو لم يكن جهاز الراديو متاحًا. لا يشغّل المحطة ولا يرسل أي إشارة.

## التوافق المتوقع وحدوده

المشروع يذكر B200 وB210 ضمن الأجهزة المدعومة، كما أن ترانسيفر UHD يصنف اللوحة بناءً على الاسم الذي يعيده UHD؛ الأسماء `B200` و`B210` تُعامل كأجهزة B2XX. لذلك يعتمد توافق USRP-2901 على الاسم الفعلي الذي يظهر في إصدار UHD المثبت وعلى نجاح فتح الجهاز وإعداد معدلات العينات. لا يوجد في المستودع ذكر صريح لـ`USRP-2901`، لذا لا يمكن تأكيد الدعم الكامل من دون الجهاز.

عند توفر USRP، افحصه أولًا باستخدام `uhd_find_devices` و`uhd_usrp_probe`. إذا ظهر باسم لا يتضمن `B200` أو `B210`، فقد يرفضه OpenBTS-UMTS باعتباره جهازًا غير مدعوم؛ لا تغيّر تصنيف الجهاز في الكود قبل التحقق من مخرجات UHD.

## تجهيز Ubuntu والبناء دون جهاز

المشروع يستهدف Linux. على Ubuntu 22.04، ثبّت أدوات البناء ومكتبات المشروع:

```sh
sudo apt update
sudo apt install -y build-essential autoconf automake libtool libtool-bin \
  pkg-config libuhd-dev uhd-host libzmq3-dev libosip2-dev libortp-dev \
  libusb-1.0-0-dev libsqlite3-dev sqlite3 libreadline-dev
```

من جذر المستودع، جهّز ملفات البناء وابنِ المشروع:

```sh
./autogen.sh
./configure
make -j"$(nproc)"
```

يتطلب بناء ASN.1 المترجم `asn1c` بالإصدار الملائم للمشروع؛ يوجد أرشيفه في `asn1c-0.9.23.tar.gz`، كما يتضمن `install_dependences.sh` خطوات تثبيت اعتماديات المشروع وتجهيز المترجم. راجع محتوى ذلك السكربت قبل تشغيله، خصوصًا إذا كانت لديك تعديلات محلية عليه.

بعد البناء، شغّل الفحص التالي من جذر المستودع:

```sh
sh tools/usrp-preflight.sh
```

هذا الفحص يتأكد من وجود أدوات ومكتبات البناء، ومن تفعيل UHD في `config.h`، ثم يحاول اكتشاف الجهاز إن كان موصولًا. عدم وجود جهاز لا يمنع إتمام التحقق البرمجي؛ نتيجة UHD وحدها لا تثبت توافق 2901.

يمكن التحقق من أن البرنامج بُني وأنه يبدأ بإظهار الإصدار باستخدام:

```sh
./apps/OpenBTS-UMTS --version
```

لا تشغّل `./apps/OpenBTS-UMTS` كاختبار بلا جهاز؛ البرنامج الرئيسي يبدأ إجراءات تهيئة الراديو. كذلك، نجاح `make` أو `--version` لا يختبر الإرسال أو الاستقبال.

## عند توفر الجهاز

1. استخدم Ubuntu مباشرة أو بيئة تضمن تمرير USB 3.0 إلى النظام، ثم افحص اكتشاف الجهاز:
   ```sh
   uhd_find_devices
   uhd_usrp_probe
   ```
2. سجّل اسم اللوحة الذي يعيده UHD وإصدارات UHD وOpenBTS-UMTS. إذا لم يكن الاسم متوافقًا مع فروع B200/B210 في `TransceiverUHD/UHDDevice.cpp`، توقّف عند هذه المرحلة.
3. لا تضبط `UMTS.Radio.Band` أو `UMTS.Radio.C0` بالتخمين. اختر النطاق ورقم UARFCN وفق الترخيص المحلي وخطة المختبر. إعداد `UMTS.Radio.C0` هو UARFCN وليس ترددًا بوحدة MHz.
4. لا توصل هوائيًا ولا تبث على الهواء إلا ضمن تصريح وتجربة معزولة ومراقبة، وبقدرة إرسال منخفضة ومناسبة. هذا المشروع قد يبدأ إرسال الراديو عند تشغيل البرنامج الرئيسي.

## ملفات الإعداد

يستخدم البرنامج قاعدة SQLite في `/etc/OpenBTS/OpenBTS-UMTS.db`. لإنشاء قاعدة جديدة فقط (لا تنفّذ ذلك فوق قاعدة موجودة):

```sh
sudo install -d /etc/OpenBTS
sudo sqlite3 /etc/OpenBTS/OpenBTS-UMTS.db < apps/OpenBTS-UMTS.example.sql
```

ملف SQL المرفق قديم مقارنة بتغييرات المشروع؛ استخدمه للتهيئة الأولية فقط، وراجع الإعدادات الخاصة بالنطاق والراديو قبل أي تشغيل. لا تبدأ تشغيل المحطة إلى أن يتوفر الجهاز وتكون بيئة الإرسال آمنة ومصرحًا بها.
